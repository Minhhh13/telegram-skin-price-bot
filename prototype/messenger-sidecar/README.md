# Messenger sidecar

This optional bridge uses the maintained [mautrix/meta](https://github.com/mautrix/meta) `messagix` client (AGPL-3.0). It reuses the existing Render Starter service and the clone account's existing `MESSENGER_COOKIES` secret. It reads only the configured `MESSENGER_THREAD_ID`, passes approved requests to the existing Node price lookup, and sends replies to that same group. No separate VM or Render service is needed.

The sidecar is **opt-in** with `MESSENGER_BACKEND=go`. The current Node listener remains the default. On Render's existing Node runtime, `npm ci` downloads the official Go 1.27.3 Linux archive, verifies its published SHA256, and builds `bin/messenger-sidecar` only when the Go backend is selected. The pinned upstream source commit is `00f9a7e24173b35572f298760166ae7a3856d59b` (6 November 2026). The binary and session secrets are not committed.

The Go process has one live socket client and a separate HTTP inbox client that polls every 60 seconds. It reads insert, upsert, and replace message rows, combines image attachments when they are in the same Lightspeed table, and passes mention IDs to Node. Images arriving in a later socket table may not be attached to an already emitted message; this is a remaining photo parity risk. Node still checks image hosts and the 5 MB limit before sending a photo to Gemini. The sidecar has a 128 MiB Go heap target; monitor total Render memory after activation because the service has previously hit its 512 MiB limit.

The build has not yet been validated on Render, and live Messenger delivery and sending have not yet been verified. A failed Go build will stop the new deploy; the previous Render release should remain active. After a successful build, verify a fresh `!buff` request in the approved group, an @mention, a photo caption, and a second request after a reconnect. The sidecar emits group message text on its stdout pipe to Node; never forward that pipe to public logs. Status diagnostics include only counts and timestamps.
